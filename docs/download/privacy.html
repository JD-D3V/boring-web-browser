The browser and your data

Browsing sends requests to the sites you visit. Searches go to your selected search provider; provider policies apply. Browser profiles can hold history, cookies, saved credentials, settings and downloads. Use a separate profile for preview testing. Uninstalling an application does not necessarily remove its profile or downloaded files.

Optional remote AI summaries can send page content to the provider you choose. Do not use them on confidential, school or personal records without permission. Local and remote processing must not be treated as interchangeable.

The browser contacts these services on its own. Each one is shown on its Protection page, and each can be changed or turned off there or in Settings:

  • Quad9 secure DNS (dns.quad9.net). The browser looks up site names through Quad9, a Swiss non-profit, over an encrypted connection, instead of through your network's resolver. Quad9 learns the names of the sites you open, as your internet provider otherwise would; it refuses to answer for known malware and phishing sites, which is how those are blocked. See Quad9's privacy policy. Change it in Settings, Privacy and security, Security, "Use secure DNS".
  • Update check (jd-d3v.github.io). About once a day an installed copy asks our site whether a newer version exists. The request carries the browser version and no identifier or cookie. A new version installs only after you agree, and only if it carries our signature. A copy run from the zip does not check. Turn the daily check off on the Protection page.
  • Blocking lists. Ad-filter rules are evaluated in the browser. This preview ships a fixed set of lists and does not download newer ones; a newer version brings newer lists.
  • Chromium Web Store (clients2.google.com, Google's extension update service). Built in, and you can remove it. It checks only if you have extensions from the Chrome Web Store. It checks about a minute after the browser starts if the last check was more than 5 hours ago, then every 5 hours. It also checks when an extension is added or removed, and when you open its menu. Turning off automatic checks in its options stops only the timed checks. It sends the ID of each Chrome Web Store extension you have and the browser version, as the user agent shows it. Google also sees your IP address, as with any request. No cookies are sent with these checks. For an extension with its own update address, it also requests that address. When you click "Add to Chrome" on a store page, the extension downloads from Google's servers like any other download. The helper never updates itself.

Import reads bookmarks, history and search engines from Chrome's or Edge's folders on this computer, only when you start an import. Nothing leaves your computer. Spellcheck downloads nothing. It uses Windows' checker or the bundled dictionary.

Measured on this build: Four runs of two minutes each on the release build: first start with the welcome page, an idle new tab, a blocking list check, and list updates turned off. A control run first proved the capture sees traffic. The only server reached was dns.quad9.net, the secure DNS resolver. Not covered by these runs: the daily update check, which only an installed copy makes, and the Chromium Web Store helper, which only makes requests when you have store extensions. This is what we saw, not a guarantee about every setting or a longer run.

Sites you visit, and the search engine you use, are contacted as you browse. They are not listed above.

Protection has limits

Known malware and phishing sites are blocked only by name, through Quad9. There is no warning page: a blocked site shows as not found. New or unreported dangerous sites are not blocked, and switching secure DNS away from Quad9 turns this protection off. No scam-site list ships with the browser. Ad/tracker blocking and popup protection are not antivirus and cannot establish that a site or download is safe. Blocking can miss unwanted content or interfere with legitimate sites. Keep Windows security protections enabled.

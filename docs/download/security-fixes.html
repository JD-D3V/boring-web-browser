SECURITY / FIXES BY RELEASE

Security fixes in each release.

Each release lists the security fixes it brings, from Chromium and in our own code. We say what was wrong in plain words, without detail that would help someone use it. This list starts with Release 3.

What each entry has

  • Release, date and Chromium version.
  • From Chromium. The version it moves from and to, with a link to Google's notes.
  • In our own code. What was wrong, in plain words, now fixed.
  • Not fixed yet. Known problems that are still open, and when we plan to fix them.
  • How we checked. Which reviews and tests the release had.

Release 3 · November 2026 · Chromium 157.0.8103.38

From Chromium

Moves from Chromium 154.0.8037.57 to 157.0.8103.38. That brings the security fixes Google shipped in Chrome 155, 156 and 157, up to that version. Google lists them on the Chrome Releases blog, in the stable channel updates for desktop. Fixes Google shipped after 157.0.8103.38 come with the next release.

In our own code

Found by our own reviews and fixed before release:

  • A guest or private window can no longer change secure DNS or automatic updates for the whole browser.
  • Blocking list updates follow a redirect only to our own list server or GitHub's file servers. Lists still have to carry our signature, as before.
  • The scam list build can no longer let one feed entry block a popular real site. An entry that is a whole domain ending, such as co.uk, is left out.
  • Turning on No way past scam warnings also removes any "continue anyway" you clicked before.
  • The look-alike warning also catches fake brand names on free hosting sites such as github.io.
  • The remote control download warning covers more file types, and file names written with accented letters.
  • Programs on this computer that talk to add-ons go through the same checks however they start.
  • Switches meant for our tests, and the folder copy setting, are harder to misuse.
  • A folder settings file that drops a regional list is marked as less protection before you load it.
  • Chromium 157's new contextual tasks side panel is kept off, because pages in it would load without our protections.
  • Features we keep off stay off, however they are asked for on the command line.

Not fixed yet

  • After Forget this session, the file that holds the tabs you closed before stays on disk until the next start. Someone who has your profile folder can read the addresses in it until then. This is Chromium's own behaviour. We plan to fix it in Release 4.
  • Locking the mouse pointer is handled by Stop screen takeovers, but was not tested in a real window.

How we checked

Five security reviews: three passes over the new code, one of the move to Chromium 157 and one of the last fixes. The whole automated test suite on the final build. Three updates from release 2 in a clean Windows Sandbox, all passed, on the build before the last small fixes. These were our own reviews, not an outside audit.

Found a security problem?

Please report it privately on GitHub (the Report a vulnerability button under the Security tab of the repository) before you post it anywhere public. Never include passwords, keys or browser profiles.
